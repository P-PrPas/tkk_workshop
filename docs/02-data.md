# 02 — ข้อมูล

## Repo
| | URL | บทบาท |
|---|---|---|
| code | `https://github.com/P-PrPas/tkk_workshop.git` | โน้ตบุ๊ก, แอป, สคริปต์, เอกสาร |
| data | `https://github.com/P-PrPas/tkk_workshop-data.git` | รูป + label + วิดีโอสำรอง |

data ผูกเป็น **submodule** ของ code ที่ path `data/` เพื่อความสะดวกตอนพัฒนา
แต่ **โน้ตบุ๊ก clone data repo ตรงๆ ด้วย URL** ไม่พึ่ง `--recursive`

> เหตุผล: ลืม `--recursive` = ได้โฟลเดอร์ว่างเปล่าโดยไม่มี error ให้เห็น
> ซึ่งเป็นอาการล้มที่วินิจฉัยยากที่สุดกลางห้องเรียน submodule มีไว้ให้เครื่องนักพัฒนา
> ไม่ได้มีไว้ให้ผู้เรียน

ตั้งค่าครั้งเดียว:
```bash
git submodule add https://github.com/P-PrPas/tkk_workshop-data.git data
git clone --recursive https://github.com/P-PrPas/tkk_workshop.git   # ฝั่งนักพัฒนา
```

## โครงสร้าง data repo
```
tkk_workshop-data/
├── cup.yaml
├── images/
│   ├── train/   (~33 ไฟล์: ~10 ในห้อง + ~23 จาก COCO)
│   ├── val/     (2 ไฟล์)
│   └── test/    (3 ไฟล์)
└── labels/
    ├── train/   (.txt ชื่อตรงกับรูป)
    ├── val/
    └── test/
```

`cup.yaml` — สคีมา COCO เต็ม 80 ชื่อ (`names: {0: person, ... 41: cup, ...}`)
ไม่ใส่ `path:` เพื่อให้ ultralytics อิงโฟลเดอร์ที่ไฟล์ yaml อยู่เป็น root
(ใส่ `path: .` จะพังบน Colab เพราะมันไปอิง cwd `/content` แทน)
```yaml
train: images/train
val: images/val
test: images/test
names:            # 80 ชื่อของ COCO ครบ — สร้างจาก YOLO("yolo11n.pt").names
  0: person
  ...
  41: cup
  ...
```

## นิยามคลาส
**`cup` = ภาชนะสำหรับดื่ม** — แก้วใส, แก้วมัค, แก้วกระดาษ, แก้วพลาสติก
**ไม่รวมขวด** (ขวดน้ำ ขวดพลาสติก กระติกน้ำ)

label ใช้ **class id 41** = `cup` ในสคีมา COCO (ไม่ใช่ 0) — โมเดลจิ๋วต้องเก็บหัว 80 คลาสไว้
ไม่งั้น 3 epoch ตรวจไม่เจอ ดู [03-models.md](03-models.md)

โมเดลรู้จักขวด (`bottle` = 39) อยู่แล้ว แต่โน้ตบุ๊กกรองด้วย `classes=[41]` เลยไม่โชว์ —
เป็น teaching moment เรื่องการกำหนดขอบเขต

## รูปในห้อง (15 ใบ) + รูปเสริม
**รูปในห้อง 15 ใบ** ถ่ายด้วยมือถือ **ในห้องและแสงเดียวกับวันงาน** — val/test ใช้รูปพวกนี้ล้วน
เพื่อวัดว่าโมเดล "ใช้ได้ในห้องนี้จริงไหม"

| ชุด | รูปในห้อง | เนื้อหา |
|---|---|---|
| train | 10 (+~23 จาก COCO) | แก้ว 2-3 ใบต่างแบบ, มุมต่างกัน, ใบเดียว/หลายใบ, บางรูปมือถือแก้ว |
| val | 2 | เหมือน train แต่คนละช็อต |
| test | 3 | **มีรูปยากอย่างน้อย 1** — แก้วใสบนพื้นสว่าง, แก้วถูกบังครึ่ง, หรือขวดวางคู่แก้ว |

**รูปเสริม ~23 ใบจาก COCO val2017** (auto-label ด้วย `yolo11m` กรอง class 41) — เติมเข้า train
อย่างเดียว เพื่อให้ conf ไม่ต่ำเกินจนต้องลด threshold เป็น 0.01 ถ้าอยากได้ผลดีกว่านี้ให้ถ่ายรูปในห้องเพิ่มแทน

ข้อกำหนดเทคนิค: JPG, ด้านยาวไม่เกิน 1280px (ไฟล์รวมควร < 5MB เพื่อให้ clone เร็ว)

## label
label อยู่ในรูปแบบ YOLO `.txt` — หนึ่งไฟล์ต่อหนึ่งรูป ชื่อตรงกัน
บรรทัดละหนึ่งกล่อง `41 cx cy w h` (41 = cup, cx/cy/w/h normalize 0-1)

label สร้างแบบ auto-label: รัน `yolo11x.pt` (COCO) กรอง class 41 แล้วเขียนกลับเป็น 41
ยกเว้น `test/IMG_7184` (มองจากบน โมเดลจับไม่ได้) ตีกล่องด้วยมือ

### สิ่งเดียวที่ต้องตรวจ
"label มีอยู่" ไม่ได้แปลว่า "label ถูกฟอร์แมต" — ความผิดพลาดสามอย่างนี้ทำให้เทรนผ่าน
โดยไม่มี error แต่ได้โมเดลที่ตรวจไม่เจออะไรเลย:

| อาการ | ผลที่เกิด |
|---|---|
| class id ไม่ใช่ `41` | ผิดคลาส — เทรนแล้วโมเดลเรียนของผิดอย่าง |
| พิกัดเป็นพิกเซล ไม่ได้ normalize | กล่องหลุดออกนอกภาพ ถูกทิ้งเงียบๆ |
| ชื่อไฟล์ .txt ไม่ตรงกับชื่อรูป | ถือว่าภาพนั้นไม่มีวัตถุ |

โน้ตบุ๊กเซลล์ 5 จึงมี assert สั้นๆ ตรวจสามข้อนี้ก่อนเทรน แล้ววาดกล่องให้ดูด้วยตา
— การเห็นกล่องอยู่ถูกที่บนรูปคือหลักฐานที่ครอบคลุมกว่า assert ใดๆ
